## 1. 태블릿 배치 (R3 §6-3 의 31)

### 1-1. 원리: `--u` 는 가로 기준, 남는 세로는 `--extra` 로 실험 화면·패널에 준다

```css
/* tokens.css */
:root {
  --u: min(calc(100vw / 1920), calc(100vh / 1080));   /* 16:9 보다 넓은 화면: 지금 그대로(양옆 띠) */
  --extra: 0px;                                        /* 세로 여유(px 길이값). 16:9 = 0 */
  --extra-max: calc(440 * var(--u));                   /* 무대 최대 1080+440 = 1520u (1250×1100 실험 화면, 거의 정사각) */
}
@media (max-aspect-ratio: 16/9) {                      /* 16:9 보다 '세로가 긴' 화면만 */
  :root {
    --u: calc(100vw / 1920);
    --extra: clamp(0px, calc(100vh - 1080 * var(--u)), var(--extra-max));
  }
}
:root { --space-slide-h: calc(1080 * var(--u) + var(--extra)); }   /* 기존 줄 수정 */
```
- 1920×1080·1280×720: 미디어쿼리는 맞지만 `100vh − 1080u = 0` → `--extra: 0px`, `--u` 도 같은 값 → **픽셀 단위로 지금과 같다**(회귀 없음). 팀장이 두 크기를 R4 전후로 겹쳐 비교한다(`tools/shot.py` 로 찍어 `python -I` 로 픽셀 diff).
- 1180×820: u 0.6146, extra 156px(=254u) → 실험 화면 660→914u. 1024×768: u 0.533, extra 192px(=360u) → 1020u. 820×1180 세로: extra 가 상한 440u 에 걸려(235px) 나머지는 위아래 종이색 띠(세로는 '깨지지 않음' 만).
- 21:9 처럼 더 넓은 화면은 지금처럼 양옆 띠(변경 없음).

### 1-3. `SK.px` 와 캔버스 축척 (sim.js)

`SK.px(n)` 이 `min(innerWidth/1920, innerHeight/1080)` 을 직접 계산하므로 미디어쿼리와 어긋난다 → **`.slide` 의 실제 폭/1920** 으로 바꾼다:
```js
SK.px = function (n) { var s = SK.el.slide || document.querySelector('.slide'); return n * ((s ? s.getBoundingClientRect().width : window.innerWidth) / 1920); };
```
`SK.canvas` 의 `fit` 모드(5종 모두 `stageFit: true`):
```js
// 지금: s = min(cw/w, ch/h); ox,oy 로 가운데 → 무대가 커져도 그림은 660 높이 그대로, 위아래 빈 칸(무대 안 레터박스)
// R4:
var s = Math.min(cw / view.w, ch / view.h);           // 축척은 그대로(16:9 회귀 없음: 660 기준 sim 은 cw/1250, 700 기준 sim 은 ch/700 → 같은 값)
view.scale = s; view.ox = (cw - view.w * s) / 2;
view.hFull = ch / s;                                   // 논리 높이 전체(16:9 = view.h)
view.extra = Math.max(0, view.hFull - view.h);         // 세로 여유(논리 단위). 16:9 = 0
view.oy = o.grow === false ? (ch - view.h * s) / 2 : 0;  // grow(기본): 위에 붙이고 extra 는 아래로. 예전 가운데 맞춤은 grow:false
view.offsetY = 0;                                      // sim 이 onResize 에서 정한다(아래)
```
- `view.clear()` 가 `ctx.translate(0, view.offsetY)` 를 마지막에 한 번 더 한다. `view.toLogical(e)` 는 `y − offsetY` 를 뺀다. → **sim 은 `onResize` 에서 `offsetY` 한 줄만 정하면 그리기·포인터가 같이 움직인다.**
- `view.w`·`view.h` 는 **설계값 그대로**(1250×660 또는 ×700) 둔다. 지금 5종이 `view.h` 를 바닥·중심선 기준으로 쓰고 있어서 바꾸면 회귀한다. 더 넓어진 영역은 `view.extra`·`view.hFull` 로만 알린다.
- `SK.stageExtra()` = `SK.view.extra` 단축. `SK.stageInset()` 은 그대로(모서리 칩은 무대 상자 기준 absolute 라 영향 없음).
- 하단 띠 캔버스(`SK.graph`·orbit `bandView`·projectile `ev`)·패널 캔버스(orbit `deepView`)는 띠·패널 상자가 그대로이므로 **손대지 않는다**.

### 1-4. 캔버스가 세로로 늘어날 때 각 시뮬레이터가 할 일 (배치 원칙 1줄 + 좌표 처리)

| sim | 원칙 | `onResize` 의 `offsetY` | 더 할 일 |
|---|---|---|---|
| projectile-energy (700 기준, 바닥 GY 636) | **바닥을 아래에 붙이고 하늘을 위로 넓힌다**(모눈 1칸 = 5 m 유지, 더 높이까지 보임) | `offsetY = extra` | 모눈·y축 눈금을 `y = -extra` 까지 그린다(`for (y = GY; y >= TOPY - extra; …)`). `L.TOP`/`SK.stageInset().top` 비교는 `−extra` 보정. 궤적이 위로 나가 잘리던 고각(90°)에서 더 보이게 되는 것은 의도. 에너지 막대·범례(stage-corner) 영향 없음. |
| double-slit-quantum (660) | **스크린(무늬)을 세로로 길게** — 광축은 중앙(`offsetY = extra/2`), 스크린 높이 `H_s + extra` 로 무늬를 더 많이 | `offsetY = extra / 2` | 스크린·확대창 높이 계산에 `+ view.extra`(무늬 샘플 수도 높이에 비례). '측정 방법 ?' 캔버스 버튼 좌표도 같이 이동(모달 중엔 **그리지 않는다** — R3 §6-3). |
| collision-momentum (660) | **트랙을 중앙에**(위 상태 칩·아래 그래프 상자 사이 균등) | `offsetY = extra / 2` | `cm-lower`(HTML, `top: 8u` 기준) 등 무대 안 HTML 조각은 상자 기준이라 그대로. 수레 끌기 `cartAt(pt)` 은 toLogical 이 보정하므로 변경 없음(확인만). 질량·속도 라벨 `ly` 계산은 stageInset 기준 그대로. |
| orbit-gravity (700 기준) | **중심 천체를 중앙에**, 궤도가 위아래로 더 보임 | `offsetY = extra / 2` | 화면 밖 판정(`y > V.h`)을 `hFull` 기준으로. 1215행 `top = max(110, inset+12)` 는 `−offsetY` 보정. |
| convex-lens (700 기준) | **광축을 중앙에** | `offsetY = extra / 2` | 물체·상 끌기(`hit`·`nearRay`) 는 toLogical 보정으로 그대로. 정면창(상의 모습)이 무대 안 HTML 이면 영향 없음. |

- 공통 검사: 1180×820·1024×768 에서 (1) 무대 위아래에 종이색 빈 칸이 없는가 (2) 끌기(수레·물체·발사점)가 손가락 자리와 맞는가 (3) 1920·1280 픽셀 diff 0.

## 2. 캔버스 기호 도우미 (R3 §6-3 의 23)

### 2-1. 글꼴 토큰 (tokens.css)

```css
--font-sans: "S-Core Dream", "Malgun Gothic", "Apple SD Gothic Neo", system-ui, sans-serif;
--font-serif: var(--font-sans);                     /* 제목도 에스코어 500 (명조 제거) */
--font-num:  var(--font-sans);                      /* 숫자 — 에스코어는 숫자 폭이 같아 tabular 불필요 */
--font-math: "Times New Roman", "Cambria", "Noto Serif KR", "Batang", "AppleMyungjo", serif;   /* 물리 기호 전용: 이탤릭 세리프 */
```
HTML 쪽도 같은 토큰: `.var__sym`·`.meter__label i`·`.sym`(신규) → `font-family: var(--font-math); font-style: italic; font-weight: 400`. (지금 `--font-serif` 이탤릭 = Noto Serif KR 이탤릭은 합성 기울임이었음.)

### 2-2. 마크업 규칙 (캔버스·HTML 공통, `$…$` 안이 수식)

| 쓰기 | 그려짐 | 규칙 |
|---|---|---|
| `$v_0$` `$v_x$` `$v_y$` `$m_1$` `$E_k$` `$v_{esc}$` | v₀ vₓ v_y m₁ Eₖ v_esc | `_` 다음 한 글자 또는 `{…}` 가 아래첨자: 크기 0.7, 기준선 +0.22em. 라틴 글자·그리스 소문자는 **이탤릭 math 글꼴**, 아래첨자 숫자·여러 글자(`esc`)는 **정체** |
| `$T^2$` `$a^3$` `$s'$` | T² a³ s′ | `^` 위첨자 0.7, −0.45em. `'` 는 프라임(′) |
| `$λ$` `$θ$` `$ω$` | 이탤릭 | 그리스 소문자 = 변수 → 이탤릭 |
| `$Δy$` `$Δp$` | Δ 정체 + y 이탤릭 | 대문자 그리스(Δ·Σ) 는 정체 |
| `$v_0$ = 20 m/s` | v₀ = 20 m/s | `$…$` 밖은 본문 글꼴(에스코어). 숫자·단위·`=` `+` `−` `×` 는 **에스코어 정체** |
| `$F$ $g$ $h$ $t$ $x$ $y$ $d$ $L$ $f$ $s$ $p$ $R$ $r$ $G$ $M$ $n$ $a$ $T$` | 이탤릭 | 한 글자 변수. 단위 기호(m, s, kg, N, J, cm, nm)는 `$` 밖에 정체로 |
| `$E_k$ = ½$mv^2$` | | `½` 는 본문 글꼴 |
| 기록 기호 `● 기록 1` | 그대로 | 색약 보조 기호는 글자로 유지 |

금지: 캔버스 문자열에 유니코드 아래첨자(`₀ ₓ ᵧ ₁ ₂`) 직접 쓰기 → 반드시 `$v_0$`. (에스코어에 `ₓ ᵧ` 글리프가 없어 다른 글꼴로 섞여 나온다.) 토스트·띠·HTML 라벨은 `rich()` 가 `$v_0$` 를 `<i class="sym">v<sub>0</sub></i>` 로 바꿔 주므로 같은 표기를 쓸 수 있다(기존 유니코드 `v₀` 도 HTML 에서는 그대로 동작 — 바꾸는 것은 선택).

### 2-3. API (sim.js §12 그리기)

```js
SK.text(ctx, str, x, y, o)   // o: {size:22, weight:400|500, color:'--color-ink', align:'left|center|right', baseline:'middle|alphabetic|top', bg:false|true, tabular:false}
                             //   str 안 $…$ 는 2-2 규칙으로, 밖은 에스코어. 반환: 그린 폭(논리 단위)
SK.measure(ctx, str, o)      // → {w, h}  (줄바꿈 없음, 한 줄)
SK.sym(ctx, 'v_0', x, y, o)  // = SK.text(ctx, '$v_0$', …) 단축
SK.font(weight, size, kind)  // → ctx.font 문자열. kind: 'sans'(기본) | 'math' | 'math-italic'. 5종의 FONT/FS/FN/font() 상수를 이것으로 통일
SK.num(ctx, '14.1', x, y, o) // 숫자 전용. o.tabular 가 true 면 '0' 폭 셀에 한 글자씩(에스코어는 숫자 폭이 같아 보통 불필요 — 글꼴이 안 떠서 대체 글꼴일 때 대비)
```
- `SK.arrow(…, {label:'$v_x$'})` · `SK.placeLabel(ctx, [{text:'$v_0$ 20 m/s'}])` 의 라벨 그리기와 폭 계산을 `SK.text`/`SK.measure` 로 바꾼다(겉 API 변경 없음).
- 구현: 토크나이저(`$` 로 나눔 → 안쪽을 `_` `^` `{}` 로 런 분해) → 런마다 `ctx.font` 바꿔 `fillText` + `measureText` 누적. 이탤릭 다음 정체 사이 0.06em 보정. 첨자 크기 0.7·오프셋은 **글자 크기 비율**이라 22/24/26 모두 같은 모양.
- 성능: 매 프레임 호출되는 곳(계기판 숫자·시간)은 `SK.measure` 결과를 캐시하지 말고 그대로(측정 1회/런, 1250 폭 한 줄 십수 개 → 무시할 수준). 다만 `cssVar('--font-sans')` 는 **init 때 1번 읽어** 캐시(지금 projectile 처럼).
- 예: `SK.text(ctx, '처음 속력 $v_0$ = ' + v + ' m/s', 40, 60, {size:24, weight:500})` · `SK.sym(ctx, 'Δy', x, y, {size:22, align:'center', bg:true})`.

```js
// 글꼴이 뒤늦게 도착하면 document.fonts.onloadingdone → SK.redraw() 한 번
```

### 3-2. API 와 CSS

```js
SK.icon('play', {size:'sm'|'md'|'lg', cls:'', label:'실행'})  // → <svg class="ico ico--md" aria-hidden="true" focusable="false">…</svg>  (label 을 주면 aria-hidden 대신 <title>)
SK.iconHTML('play')                                            // 문자열(innerHTML·템플릿용)
SK.iconPath('play')                                            // 캔버스용 Path2D 생성 글자열(24×24 좌표) — slit '측정 방법 ?' · lens 캔버스 버튼
SK.ICONS                                                        // {name: '<path d=…>'} 원본 (24×24 viewBox, stroke 2, round cap/join, fill none; play·pause·check-fill 은 fill)
```
```css
.ico { display: inline-block; width: 1em; height: 1em; vertical-align: -0.12em; flex: none; stroke: currentColor; fill: none; stroke-width: 2; stroke-linecap: round; stroke-linejoin: round; }
.ico--sm { font-size: calc(20 * var(--u)); }  .ico--md { font-size: calc(24 * var(--u)); }  .ico--lg { font-size: calc(32 * var(--u)); }
.ico.is-fill { fill: currentColor; stroke: none; }
.btn > .ico:first-child { margin-right: var(--space-2); }  .btn > .ico:last-child { margin-left: var(--space-2); }   /* 글자와 간격 8u */
```
- **크기 규칙**: 글자 옆 아이콘은 크기를 주지 않으면 **부모 글자 크기의 1em**(버튼 28u → 28u). 범례·칩 안은 `sm`, 캔버스 안 버튼·주 버튼 `lg`.
- **정렬 규칙**: 버튼·칩은 이미 `inline-flex; align-items:center` 라 가운데 정렬. 본문 글 속은 `vertical-align: -0.12em`(x-height 중심). 아이콘만 있는 버튼(`✕`)은 `aria-label` 필수.
- **자동 치환**: `btn(label)`·`h('span',{text})` 를 거치지 않는 곳이 많으므로 **`SK.iconify(el)`**: 요소 텍스트 노드의 **맨 앞/맨 뒤** 글자 기호(3-1 표)만 아이콘으로 바꾼다(가운데 `10 → 20` 은 안 건드림). `btn()`·`notice()`·`updateTask()`·`updateTransport()`·메뉴 생성에서 호출. 5종은 자기 버튼(`SK.btn` 로 만든 것은 자동)과 자체 HTML 에 `SK.iconify(root)` 한 번.
- **CSS `content:` 글자**(`.panel-deep summary::after "▾ 펼치기"`, `.preset-card.is-reco::before` 등 base.css 11곳): `::after` 에는 글자만 남기고 아이콘은 `mask-image: var(--ico-chev-down)` 로 — `tokens.css` 에 `--ico-chev-down: url("data:image/svg+xml,…")` 4개(chev-down·chev-up·check·bolt)만 데이터 URI 로 두고 `background-color: currentColor` 로 칠한다(file:// 동작, 색은 currentColor).
- 허브 `index.html` 의 `← 허브`·카드 `열기 ▸` 도 `SK` 없이 쓰므로 `shared/icons.js` 는 **`window.SimIcons`** 로도 노출(허브가 `SimIcons.html('chev-right')`).
