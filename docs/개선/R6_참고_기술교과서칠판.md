## 1. 참고 사이트에서 가져올 원칙·수치

### 1-1. 한 벌의 토큰, 화면 종류별 숫자 (가장 중요)
- 칠판은 설계 화면 **1920×1080, 1u = 설계 1px**, `--u = min(100vw/1920, 100vh/1080)`. 크기·글자·간격 모두 `calc(N * var(--u))` 로만 쓴다 (`tokens.css:1-11`, `:285-289`).
- 화면 종류는 클래스로 나눈다: `sf-board`(칠판) / `sf-phone` / `sf-desk`. 한 벌의 토큰 이름에 화면마다 다른 숫자를 푼다 (`:316-370`, `:382-538`).
  - 적용: 심플 모드도 `html.is-simple` 한 클래스로 토큰만 바꾸고, DOM·상태는 그대로 둔다. "모드를 바꿔도 값 유지" 가 구조적으로 보장된다.
- 글자는 **역할마다 한 크기** (`:295-314` 표). 같은 역할은 어느 장에서나 같은 크기, 장마다 줄이거나 키우지 않는다. 칠판 값: 표지 숫자 96 · 제목 56 · 요점 64 · 본문 40 · 캡션 32 · 표시 28 · 단추 32, **글자 하한 28** (`:336-353`).
- 넘치면 글자를 줄이지 않고 ① 그림 칸 폭 42→34→28% ② 간격 ×0.75(바닥 있음) 순서로 줄인다 (`:371-379`, `:426-472`). 간격은 5개 토큰(top/tag/title/box/group = 40/20/28/32/48u)만 쓴다.

### 1-2. 누름 크기·간격

|---|---|---|

| 누름 사이 | 12u 이상 (`--bd-gap`), 큰 단위 16u | `board.css:87`, `tokens.css:486` |
| 아래 막대 | 높이 88u, 안의 단추 72u, 이전 176×72 · 다음 256×72 · 도구 88×72 (아이콘 32 + 꼬리표 22) | `tokens.css:474-497`, `board.css:231-235` |
| 머리줄 | 단원색 띠 12u + 글자칸 72u, 보여 주기만(터치 없음) | `board.css:94-102` |
| 둥글기 | 칠판 12/20/32u, 휴대폰 8/14/20, 알약 999 | `tokens.css:499`, `:407` |
| 테두리·초점 | 테두리 4u, 단원 윗선 8u, 초점 고리 6u | `:500-502` |

- 사용자가 말한 "44/56/64, radius 10/16/24/999" 는 `IMPROVEMENT_RULES.md:151`(R23)에 있는 천재·동아 공통 문구다. 실제 토큰은 **데스크 44, 데스크 머리줄 56, 칠판 64**(`tokens.css:517-520`, `:483`)로 나뉘어 있어 같은 계열이다. 둥글기는 이 파일에서 10/16/24 가 아니라 칠판 12/20/32 이다. 이 프로젝트는 **칠판=64u, 태블릿(터치)=56u, 노트북 마우스 보조=44u** 로 옮겨 쓰면 된다.
- 굵기: 글꼴 에스코어 드림 300/400/500 (`fonts.css:13,21,29`). 다만 dongatech 는 제목·단추에 700도 많이 써서(`board.css:145,180,269`) **이 프로젝트의 300/400/500 제약이 더 엄격하다**. 가져오지 않는다.

### 1-3. 색과 대비
- 칠판은 대비 **7:1** 로 따로 진하게 푼다 (`tokens.css:157-176`): 휴대폰·데스크는 4.5:1, 칠판은 글자색이 될 수 있는 모든 색을 가장 진한 바탕 위에서 7:1. 상태색(정답·오답·경고)도 칠판용 더 진한 값을 쓴다.
- **흐림(opacity) 대신 토큰**: 비활성은 `opacity` 가 아니라 점선 테두리 + 보조 글자색 (`board.css:312-313`, `tokens.css:250-257` 끝 문장). 색만으로 알리지 않고 기호·낱말을 같이 쓴다 (`:104`).
- 단원색 윗선(12u 띠)을 머리줄 맨 위에 둔다 (`board.css:100`). → 이 프로젝트는 시뮬레이터 5종이 각자 대표색을 가지므로 그 색을 띠로 쓰면 허브에서 들어온 화면과 이어진다.
- 층(z) 토큰 한 줄 정리: 무대 1 · 판서 20 · 막대 30 · 도구 판 35 · 시트 40 · 쪽지 45 · 덮개 50 · 알림 55 · 가림 60 (`:549-561`).

### 1-4. 전자칠판 도구 배치와 터치 영역
- "**누를 것은 y≥360 아래**": 머리줄은 보여 주기만, 시트·도구 판의 위 끝도 360 아래 (`board.css:11`, `:88`, `tokens.css:404`, `:498`). 교실 칠판이 높아 어린 학생·키 작은 교사가 위를 못 누르는 문제.
- 아래 막대 한 줄에 `[이전] [도구들…] ▬진행▬ n/N [차례] [다음]`. 도구는 아이콘 위·글자 꼬리표 아래 (`board.css:293-313`). 도구 판은 막대 위로 **올라오는 시트**(`.bd-panel`, 200ms)이고, 많은 기능은 `⋯ 더보기` 한 판에 모은다 (`board.css:78-79`).
- 길게 누르기(600ms)로 공개하는 진행 고리, '한 번 더 누르면 처음부터'(.again.is-confirm) 확인 방식 (`board.css:44`, `:69`). → 되돌리기·기록 지우기에 쓸 수 있다.
- 가장자리 넘김 띠(폭 96)와 판서 중 띠 숨김 (`board.css:194-216`)은 **넘김이 없는 이 프로젝트에는 쓰지 않는다**(2절).

### 1-5. 넘김·화면 통일 규칙(R21~R25)에서 가져올 것
- **같은 역할은 같은 자리·같은 모양** (R22, `IMPROVEMENT_RULES.md:150`). 제목·단추가 모드를 바꿔도 안 움직여야 한다 → 심플/자세히 토글은 두 모드에서 같은 위치.
- **안내문 금지, 도움말은 세 방식만**: ① ? 단추 ② title 툴팁 ③ 처음 한 번만 뜨는 토스트(저장 키로 1회) (같은 줄). → 심플 모드 첫 진입 때 토스트 1회.
- 설명 문단·통계 문구·개발 문구를 화면 첫머리에 두지 않는다. 제목·메타는 한 줄, 넘치면 말줄임 (`board.css:118-127`).
- 켬·끔 단추 `aria-pressed`, 현재 위치 `aria-current`, 누름 44px 이상, 칠판 들고 나올 때 초점 이동 (R24, `:152`). 토글은 `role="switch"` 또는 `aria-pressed` 한 쌍으로.
- localStorage 읽기는 try/catch (R25, `:153`) — 이 프로젝트 제약과 같다.
- 화면 용어는 한 파일에서만 (R20, `:138-142`): '심플'·'자세히' 낱말도 `shared/` 한 곳에 둔다.

### 2-1. 토글 위치 결정
- 머리줄 오른쪽 **분절 토글 `[심플 | 자세히]`**(288×64u, 선택 쪽 진한 바탕 + 체크 기호). 두 모드에서 같은 자리(R22).
- 아래 막대 맨 오른쪽에도 같은 토글을 둘 필요는 없지만, 심플 모드 막대의 `⋯ 더 보기` 판 맨 위에 `자세히 모드로 ▸` 한 줄을 둔다(y≥360 규칙, 칠판 높은 곳 대비).
- 단축키: 비어 있는 키(제안 `M`)를 `sim.js` 에서 확인 후 지정. 입력칸 위에서는 끔(R21 조작 규칙, `IMPROVEMENT_RULES.md:149`).

## 3. 심플 모드 화면 배치 시안

### 3-0. 설계 원칙 (심플 모드 8줄)
1. **실험 화면이 주인공**: 무대 면적 일반 모드의 약 1.15배(그림 한가운데를 가리는 예측 창은 기본 접힘).
2. **변수 3개 이하**, 큰 슬라이더 + 큰 −/+ + 현재값 72u. 숫자 입력칸은 값을 누르면 키패드(기존 기능 유지, 평소엔 숨김).
3. **측정값 3개 이하**, 값 64~72u + 라벨 32u. 막대·띠 같은 그림형 측정은 1개만.
4. **큰 실행·다시** 단추, 나머지는 `⋯ 더 보기` 한 판(단계 흐름·기록 표·정리 질문·실험 카드 5개·한 장면씩·속도·기본값).
5. 글자 하한 **28u**, 값 64~72u, 제목 44u. 굵기 400/500 만.
6. 누름 **64u 이상**(터치 기기 56u), 사이 16u 이상. 비활성은 점선 + 보조색, 흐림(opacity) 금지.
7. 한 화면에 두 겹 스크롤 없음. 스크롤 패널 자체를 없애 값 3개가 늘 한 번에 보인다.
8. 모드 전환은 **같은 DOM 에서 CSS 와 `hidden` 만 바꾼다**(재렌더 없음) → 값·실행 위치·기록 모두 유지.

- 오른쪽 변수 레일은 **아래 정렬**(카드 1 이 y168~416, 2·3 은 y≥440)이라 가장 자주 만지는 두 변수가 y≥360 에 있다.

- 결과 해설은 무대 아래 측정 칸 대신 **측정 3 자리를 `왜 그럴까? ▸` 칩**으로 바꿔 시트로 열기(두 겹 스크롤 없음).
- 1280×720(u≈0.667): 글자 하한 28u ≈ 18.7px, 값 64u ≈ 43px, 누름 64u ≈ 43px(마우스·펜 충분, 손가락은 보조). 위 좌표는 모두 그대로 비례 축소된다.
- 1180×820 / 1024×768 (4:3): u = 너비/1920 ≈ 0.61/0.53 이므로 글자가 너무 작아진다. **4:3 이하에서는 변수 레일을 무대 아래로 내리고(3-2 세로 틀의 가로 변형) 무대만 `1fr`** 로 늘린다. 글자 하한은 px 로 **18px 밑으로 내리지 않는다**(`max()`).

### 3-4. 허브 `index.html` 의 모드 선택
- 1920 허브 머리줄 오른쪽에 같은 분절 토글 `[심플|자세히]`(288×64). 선택하면 5개 카드의 링크가 `?simple=1` 또는 `?simple=0` 을 붙이고(혹은 sim 이 `localStorage` 값을 읽음), 카드 한 장마다 작은 칩 `심플` 을 표시.
- 저장 키는 허브·sim 이 같은 키 하나(`physsim-mode`, try/catch). URL 쿼리가 있으면 쿼리가 이기고 선택을 덮어쓴다.
- 첫 진입(저장 없음): 허브는 자세히, 새 사용자가 `?simple=1` 로 들어오면 심플. 심플 첫 진입 때만 토스트 1회 "자세히는 오른쪽 위에서 바꿔요"(R22 세 번째 방식, 저장 키로 1회).

### 3-5. 전환 동작 (구현 지침, 디자인 요구)
- `html.is-simple` 를 붙이고 떼는 것만으로 전환. 변수·실행 위치·기록·예측 입력·선택한 실험 카드를 **다시 만들지 않는다**.
- 전환 중 실행이 돌고 있으면 그대로 돈다(막대의 `■ 멈춤` 은 같은 자리·같은 크기).
- 무대 크기가 바뀌므로 `ResizeObserver` 한 번에 캔버스 좌표를 다시 계산(깜빡임 없이 120ms 투명도만).
- `prefers-reduced-motion` 이면 시트·전환 시간 0.

## 4. 일반(자세히) 모드에도 적용하면 좋을 것

**4-1. 지금 화면을 보고 찾은 것 (1920 일반 모드, 촬영 기준)**
1. 보조 글자가 약 22~24px 로 보이는 곳이 많다: 슬라이더 힌트('0~30 m/s · 버튼 한 번에 1'), 실험 카드 둘째 줄('h 20 m · 0°'), `(최대 5)`, 측정 칸 라벨. dongatech 칠판 하한 28u 와 비교하면 작다. 16:9 좌표를 못 바꾸는 일반 모드에서는 **하한을 24u 로 올리는 것까지만** 권한다(회귀 위험).
2. 비활성·기록 없음 같은 상태가 `opacity` 로 흐릴 가능성이 있는 곳(예: '예측하기' 단추가 활성 전 누르스름한 판)은 **점선 테두리 + 보조 글자색**으로(`board.css:313`).
3. `기본값으로 되돌리기`·표 지우기 같은 되돌리기는 **'한 번 더 누르면 처음부터'** 2단계 확인 하나로 통일(`board.css:69`).
4. 실험 카드 5개·한 장면 뒤/앞·속도·기본값·그 밖의 기능이 막대 아래 두 줄에 모두 있다. 칠판 막대 규칙(한 줄 88u, 도구는 아이콘+꼬리표 `⋯ 더보기` 로 묶기, `board.css:78-79`)을 따르면 줄이 하나 줄지만 **16:9 일반 배치 회귀 금지**이므로, 일반 모드에서는 지금 배치 유지 + 다음 R7 에 검토.
5. 머리줄·막대 높이·단추 폭이 모드 사이에서 움직이지 않게(R21 고정 자리). 특히 `실행` 은 실행 중 `멈춤` 으로 바뀌어도 폭을 같게.
6. 1280 이하에서 글자가 `--u` 비례로 같이 작아지면 18px 밑으로 가지 않게 `max()` 하한(`tokens.css:319` 방식)을 둔다.
7. 단원(대표)색 윗선 12u 를 일반 모드 머리줄에도 둬서 허브 카드 색과 이어지게(지금은 1단계 밑줄만 색이 있음).
8. z 층 토큰 도입(시트 40, 알림 55 등)으로 팝업·예측 창·도움말이 서로 가리는 문제 정리.

**4-3. 우선순위 제안 (개발 순서)**
1. `shared/tokens.css` 에 `html.is-simple` 토큰 블록(3-0 수치)과 `--u` 계산 추가. 2. `shell.css` 에 심플 배치(레일·측정 칸·막대·시트). 3. `sim.js` 의 mode 상태(쿼리·저장·토글·키). 4. 5개 sim 의 `simple:{vars,reads,prompt}` 선언 데이터(3-3). 5. 허브 토글. 6. 4-2 R5 남은 것. 7. 시각 검사(1920·1280·1180·1024·820 세로, 심플/자세히 각각) + 모드 왕복 후 값 유지 확인.
